The Keras toolkit

Optimizers, regularizers, callbacks — and the diagnostic table that tells you which one you need. Built from Lesson 3 and Lesson 4.

1The whole shape of a training script

from tensorflow import keras
from tensorflow.keras import layers, regularizers, callbacks

# ---- 1. BUILD: architecture + regularizers live here ----------------
model = keras.Sequential([
    layers.Input(shape=(n_features,)),
    layers.Dense(128, activation='relu',
                 kernel_regularizer=regularizers.L2(1e-4)),
    layers.Dropout(0.3),
    layers.Dense(64, activation='relu'),
    layers.Dropout(0.3),
    layers.Dense(1)                      # <- from the activation cheat sheet
])

# ---- 2. COMPILE: optimizer + loss + what to watch -------------------
model.compile(
    optimizer=keras.optimizers.Adam(learning_rate=1e-3),
    loss='mse',
    metrics=['mae']
)

# ---- 3. FIT: callbacks live here ------------------------------------
history = model.fit(
    X_train, y_train,
    validation_data=(X_val, y_val),   # callbacks need this to watch val_loss
    epochs=1000,                      # deliberately huge; EarlyStopping decides
    batch_size=32,
    callbacks=[
        callbacks.EarlyStopping(monitor='val_loss', patience=15,
                                restore_best_weights=True),
        callbacks.ReduceLROnPlateau(monitor='val_loss', factor=0.5,
                                    patience=5, min_lr=1e-6),
        callbacks.ModelCheckpoint('best.keras', save_best_only=True),
    ]
)
The mental model

Build decides what the model can represent. Compile decides how it searches. Fit decides when to stop, what to save, and when to slow down. Regularizers go in step 1, optimizers in step 2, callbacks in step 3 — if you can place a tool on that map, you know how to use it.

Adam's hyperparameters, and whether to touch them: learning_rate=0.001 — yes, this is the one knob worth tuning. beta_1=0.9 (momentum decay), beta_2=0.999 (RMS decay), epsilon=1e-7 — leave all three alone.[1]

3Regularizers — build time

ToolCodeWhat it doesTypical
Fewer units Dense(32) not Dense(512) Less capacity to memorise. The cheapest, most under-used regularizer. Try first
L2
weight decay		 kernel_regularizer=regularizers.L2(1e-4) Adds l2 × Σw² to the loss. Big weights cost something, so the fit gets smoother. 1e-5…1e-3
L1 kernel_regularizer=regularizers.L1(1e-5) Adds l1 × Σ|w|. Drives weights to exactly zero — sparsity, feature selection. Rare in nets
Dropout layers.Dropout(0.3) Zeroes a random 30% of units each training step. Forces redundant, independent features. 0.2…0.5
BatchNorm layers.BatchNormalization() Normalises each layer's inputs. Mainly stabilises and speeds training; regularizes as a side effect. After Dense
More data — The only one with no downside. Beats every technique in this table. Always
Three things that catch people
  • Dropout is a layer, placed after the layer it thins. Keras disables it automatically at prediction time — never do that by hand.
  • kernel_regularizer penalises weights (what you want). activity_regularizer penalises outputs (a different, rarer intent). bias_regularizer is almost never useful.
  • A regularizer should make your training loss slightly worse. If it does not, it is not doing anything.

The default that costs people models

EarlyStopping(restore_best_weights=False) is the Keras default.[2] Without it you stop patience epochs after the best model and keep the degraded weights. Set it to True. Every time.
